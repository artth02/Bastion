01 · Why Bastion

A message bus your frontend can talk to.

Bastion doesn't care what you send. Objects, arrays, strings, numbers: it only carries them to the right sockets. You decide who listens.

Channels

Sockets join one or more channels with bastion-join and a custom id of your choice, such as a user or a device.

Emit or broadcast

Emit reaches everyone on the channel, sender included. Broadcast reaches everyone except the sender. Both arrive as bastion-notification.

Push from any backend

No socket needed server-side: POST to /bastion/notification with a list of channels, or let Bastion subscribe to an AWS SNS topic.

02 · Quick start

Running in a minute.

One container, two ports: the HTTP API on 10007 and Socket.IO on 10008.

  1. Start itdocker-compose up, or npm install && npm start on Node 26.
  2. ConnectLoad the Socket.IO client from Bastion and open the /bastion/notification namespace.
  3. JoinEmit bastion-join with your custom id and the channels to listen on.
  4. ListenHandle bastion-notification. Send from a socket, or POST from your API.
// <script src="http://bastionHost:10008/socket.io/socket.io.js">
const socket = io.connect('http://bastionHost:10008/bastion/notification')

socket.on('connect', () => {
  socket.emit('bastion-join', { customId: userId }, 'orders')
})

socket.on('bastion-notification', (notification) => {
  render(notification)
})

// everyone on #orders except me
socket.emit('bastion-broadcast-notification',
  { notification: { id: 42, status: 'shipped' } }, 'orders')
POST http://bastionHost:10007/bastion/notification
Content-Type: application/json

{
  "meta": { "channels": ["orders", "index"] },
  "notification": { "id": 42, "status": "shipped" }
}

# 200 OK  →  every socket on #orders and #index
#           receives bastion-notification
# API on :10007, Socket.IO on :10008, 4 workers
$ docker-compose up

# or by hand (Node 26+)
$ npm install
$ PORT=10007 IOPORT=10008 CLUSTER=4 npm start

# is it up?
$ curl http://localhost:10007/bastion/healthcheck/ping

03 · Scale out

More cores, more nodes, same channels.

Set CLUSTER and Bastion forks one worker per core, restarting any that die. Run several nodes and point SOCKET_BROKER at a shared broker: every message is synced across nodes, so a socket on node A still hears a POST that hit node B.

Each node connects to the broker as a client and joins two sync channels, one for emits and one for broadcasts. A message enters once, fans out to every node, and each node delivers to its own sockets.

04 · API at a glance

Four events, four endpoints.

Socket.IO namespace /bastion/notification on the IO port; HTTP routes on the API port, with Swagger docs built in.

Socket eventWhat it does
bastion-joinJoin channels with a custom id
bastion-emit-notificationSend to the channel, sender included
bastion-broadcast-notificationSend to the channel, sender excluded
bastion-notificationWhat every listener receives
HTTP routeWhat it does
POST/bastion/notificationPush to a list of channels
GET/bastion/inspect/channelsChannels and socket counts
GET/bastion/inspect/channels/{name}Sockets in one channel
GET/bastion/healthcheck/pingLiveness check
